## Key Observations

- **High baseline (77Mi):** The perses-operator was not restarted between Run 4 and Run 5. It retained residual memory from the prior 600-dashboard reconciliation, settling at 77Mi instead of the typical 20Mi fresh-start baseline.
- **Memory growth under load was modest:** 77Mi → 122Mi (+45Mi for 600 dashboards). Compare with fresh-start runs where growth was 20Mi → 92-108Mi (+72-88Mi). This suggests the operator reuses existing allocations when warm.
- **Recovery is near-complete:** Post-deletion memory (76Mi) returned to within 1Mi of baseline (77Mi), demonstrating effective cleanup even from a warm start.
- **Perses operator actual (122Mi) is near its 128Mi request:** At 95% of request, this is the highest utilization observed. Under heavier dashboard load, the operator would exceed its request (though still well within the 512Mi limit).
