## Failure Analysis

The memory recovery check failed marginally:

- Baseline: 20Mi
- Post-deletion (best): 43Mi
- Threshold: 40Mi (2x baseline)
- **Overshoot: 3Mi above threshold**

This is a borderline result. The perses-operator recovered from 105Mi down to 43Mi (a 59% reduction), but the 2x-baseline threshold of 40Mi is very tight with a 20Mi baseline. For comparison, the earlier run (17:47) had a 23Mi baseline → 46Mi threshold → 44Mi actual, which passed by just 2Mi.

**Contributing factors:**
- Lower baseline in this run (20Mi vs 23Mi in the prior run) makes the threshold stricter
- The operator did recover significantly (105Mi → 43Mi), indicating the PR #414 fix is working
- Residual 23Mi above baseline could be Go runtime heap retention (not a true leak)
